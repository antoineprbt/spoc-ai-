## Product concept

Product name: BLACKSITE
Tagline: “See the signal. Understand the incident.”

BLACKSITE is a simulated crisis-operations intelligence dashboard. It combines authorized or simulated camera observations, sensor readings, and field reports into one operational picture. It detects unusual events, links related signals, and explains why an analyst should review them.

The app is for understanding a simulated crisis, not directing real-world military operations. Use a wholly fictional facility and entirely synthetic data. Do not connect to real cameras, external surveillance systems, real military networks, or live operational feeds. Do not implement face recognition, person identification, target selection, weapon guidance, or tactical attack recommendations. The dashboard must clearly label itself “SIMULATION — SYNTHETIC DATA ONLY.”

## Core demo scenario

Create a fictional facility called “Northstar Station” and a fictional crisis scenario called “Nightfall.”

The scenario should include a short timeline of synthetic signals, for example:
- A power-quality sensor reports an unusual voltage fluctuation in one zone.
- A synthetic camera observation reports a visual anomaly, such as smoke-like haze or an unexpected blocked corridor. Represent camera feeds with generated or clearly synthetic visuals/placeholders, not real surveillance footage.
- A synthetic field report mentions a local equipment fault.
- A second sensor reading either corroborates or contradicts the initial signal.

The user should be able to press a clear “Run simulation” button and see the application process these events. Include at least one alternative scenario or a control that changes the event stream so the output visibly changes.

## AI functionality: make it real, explainable, and reproducible

Implement actual local computation, not just static AI labels:
- Use anomaly detection on deterministic synthetic multivariate sensor data. A suitable approach is scikit-learn IsolationForest, with a fixed random seed and documented features.
- Use event correlation to link signals by time, zone, and event type. Show the related events and explain the correlation in plain language.
- Represent the facility and its zones/sensors/events as a graph using a suitable lightweight method, such as NetworkX. Show a simple incident graph or dependency view.
- Compute a transparent incident-priority score from anomaly score, corroborating signals, and event severity. Display the factors that contributed to the score.
- Make uncertainty visible: distinguish detected anomalies from confirmed facts and clearly state when an analyst needs to verify an alert.
- Do not imply that the system can predict attacks or determine who caused an incident.

If a dependency is unavailable or installing it would put the deadline at risk, implement a transparent, documented fallback with standard Python. Do not fabricate model performance or claim an algorithm is being used unless the code actually uses it.
